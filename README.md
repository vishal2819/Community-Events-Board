# Civic — Community Events Board

A neighbourhood cultural board for discovering local events across Indian cities. Visitors
browse and filter public events, save favourite categories for a personalised feed, set
reminders, and design a personal event card. Administrators manage the event catalogue.

Built as a single Next.js App Router application with PostgreSQL and Prisma.

---

## Stack

| Concern | Choice |
|---|---|
| Framework | Next.js 16 (App Router, Turbopack) |
| Language | TypeScript 5.9, `strict` |
| Database | PostgreSQL 16 via Prisma 6 |
| Auth | bcrypt (cost 12) + `jose` HS256 JWT |
| Styling | Tailwind CSS v4, shadcn/ui on Radix |
| Data fetching | TanStack Query, clients generated by Orval |
| Tests | Vitest |
| Monorepo | pnpm workspaces |

## Setup

**1. Install dependencies**

```bash
pnpm install
```

**2. Start PostgreSQL**

Using Docker:

```bash
docker run -d --name civic-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=civic -p 5432:5432 postgres:16
```

**3. Configure the environment**

```bash
cp artifacts/community-events/.env.example artifacts/community-events/.env
```

Then edit `artifacts/community-events/.env`:

```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/civic"
JWT_SECRET="<at least 32 cryptographically random bytes>"
ADMIN_EMAIL="admin@example.com"
ADMIN_PASSWORD_HASH="<bcrypt cost-12 hash>"
```

Generate `JWT_SECRET` with:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

Generate `ADMIN_PASSWORD_HASH` with the interactive helper, which hides the input:

```bash
cd artifacts/community-events && pnpm admin:hash
```

Paste the printed hash into `.env`. Never commit a plaintext password or a real
production secret.

**4. Create the schema and seed data**

```bash
cd artifacts/community-events
pnpm db:generate     # generate the Prisma client
pnpm db:migrate      # apply committed migrations
pnpm db:seed         # insert 18 events, idempotent
```

**5. Run the app**

```bash
pnpm dev
```

Open <http://localhost:3000>.

## API

The JSON API is served by Next.js Route Handlers under `/api`, described by
`lib/api-spec/openapi.yaml`. That spec is the single source of truth: after editing
it, regenerate the Zod schemas and the React Query client.

```bash
cd lib/api-spec && pnpm codegen
```

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/api/healthz` | public | Liveness check |
| POST | `/api/auth/signup` | public | Create a visitor account and sign in |
| POST | `/api/auth/login` | public | Exchange credentials for a token and cookie |
| POST | `/api/auth/logout` | any | Clear the session cookie |
| GET | `/api/auth/me` | optional | Current identity, or `null` |
| GET | `/api/events` | optional | Filtered, paginated upcoming events |
| GET | `/api/events/meta` | public | Cities and category counts |
| GET | `/api/events/[id]` | optional | Single active upcoming event |
| GET | `/api/feed` | visitor | Upcoming events in saved categories |
| GET | `/api/favourites` | visitor | Saved categories |
| PUT | `/api/favourites` | visitor | Replace saved categories |
| GET | `/api/reminders` | visitor | Saved reminders |
| PUT | `/api/events/[id]/reminder` | visitor | Save a reminder (idempotent) |
| DELETE | `/api/events/[id]/reminder` | visitor | Remove a reminder (idempotent) |
| GET | `/api/events/[id]/card-design` | visitor | Saved card design, or the default |
| PUT | `/api/events/[id]/card-design` | visitor | Persist a card design |
| GET | `/api/admin/events` | admin | All events, including past and inactive |
| POST | `/api/admin/events` | admin | Create an event |
| GET | `/api/admin/events/[id]` | admin | Event for editing |
| PATCH | `/api/admin/events/[id]` | admin | Update an event |

Browsers authenticate with an `HttpOnly` cookie. API clients send
`Authorization: Bearer <token>`; both resolve to the same services.

## Testing

```bash
cd artifacts/community-events && pnpm test
```

98 unit tests cover request validation, JWT issuing and verification, CSRF origin
checks, rate limiting, event filter composition, DTO field exposure, and request body
parsing limits. They need no database.

Database-backed integration tests and browser end-to-end tests are not implemented. Do
not claim they ran.

## Security notes

- Passwords are bcrypt cost 12. Login compares against a dummy hash when an account is
  missing, so response timing does not reveal whether an email is registered.
- JWTs are HS256 with a pinned algorithm, issuer, audience and required claims. Sessions
  expire after 8 hours.
- Sessions are stored in an `HttpOnly`, `SameSite=Lax` cookie, marked `Secure` in
  production. Tokens are never returned in page HTML.
- Mutating routes enforce a same-origin `Origin` check. Bearer clients without ambient
  cookies may omit it.
- Login and signup are rate limited per account. Client IP bucketing is opt-in via
  `AUTH_TRUSTED_IP_HEADER`, because forwarded headers are otherwise caller-controlled.
  Rate limiting is in-process and suits a single instance only.
- Request bodies are capped at 16 KB and responses are `Cache-Control: no-store`.
- Unexpected errors return a generic message; internal error text, connection strings and
  Prisma messages are never logged or returned.
- Admin access requires both `ADMIN_EMAIL` and `ADMIN_PASSWORD_HASH`. The admin is a
  single environment-provisioned account with no database row, and can be disabled by
  unsetting either variable.
- Migrations and seeding never run at application startup or build time.

## Repository layout

```
artifacts/community-events   Main application
artifacts/mockup-sandbox     Vite prototype, reference only
artifacts/api-server         Express template, unused by the app
lib/api-spec                 OpenAPI spec and Orval codegen
lib/api-zod                  Generated Zod schemas
lib/api-client-react         Generated React Query client
lib/db                       Drizzle template, unused by the app
scripts                      Utility scripts
```

The app talks to the database only through `artifacts/community-events/src/lib/db`. The
unused `lib/db` and `artifacts/api-server` packages are workspace templates, not
application code.
